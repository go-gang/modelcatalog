# Формат каталога

Инструмент создаёт два JSON-файла в UTF-8 с завершающим переводом строки.
Порядок записей воспроизводим; текущая дата машины не влияет на результат.

## Manifest

`snapshot.json` содержит:

| Поле | Значение |
| --- | --- |
| `schema_version` | Версия формата manifest, сейчас `1`. |
| `revision` | Ревизия снимка. |
| `profile` | Профиль отбора, сейчас `text-streaming-functions-v1`. |
| `retrieved_date` | Дата снимка в формате `YYYY-MM-DD`. |
| `sources` | Публичные URL источников metadata. |
| `catalog_sha256` | SHA256 полных байтов `models.json`, lowercase hex. |

Потребитель проверяет hash и отклоняет неподдерживаемые версии и профили.
Ревизия фиксирует снимок и не гарантирует, что модель всё ещё доступна
на момент запуска приложения.

## Записи моделей

`models.json` содержит `version: 1` и массив `models`, отсортированный
по паре `provider` и `id`. Сейчас используются `openai`, `openai-codex`,
`anthropic` и `openrouter`. ID и документированные aliases сохраняются
буквально, включая namespace и суффиксы OpenRouter.

Необязательные `name`, `capabilities`, `protocol` и `pricing` описывают модель.
Поля различают отсутствие значения, `null` и известное значение:

- Отсутствующее поле не задаёт значение; при слиянии слоёв оно может наследоваться.
- `null` явно отмечает unknown и закрывает унаследованное значение.
- Известное значение применяется явно, включая `false`, нулевую цену и пустой список.

`capabilities` описывает инструменты, изображения, system messages, streaming,
reasoning, точные уровни reasoning и лимиты токенов. Отсутствующий или unknown
список уровней нельзя достраивать по названию семейства модели.

`protocol.api` задаёт семейство сериализации: `openai_chat`, `openai_responses`,
`openai_codex_responses` или `anthropic_messages`. Compatibility-блок содержит
настройки этого семейства, но не адрес API или credentials. Ограничения
своего транспорта потребитель применяет отдельно.

`supports_temperature`, `supports_top_p` и `allowed_sampling_thinking`
описывают поддержку sampling в выбранном профиле. Provenance разделяет
сведения провайдера, ограничения профиля и неизвестные значения.
Ограничение профиля не означает, что провайдер запрещает все остальные варианты.

## Цены

Известная цена содержит `source`, `version` и доступные тарифы ввода, вывода,
чтения и записи кэша в USD за миллион токенов. Отсутствующий тариф остаётся
unknown. Нулевая цена известна и может обозначать бесплатный вариант.

`max_input_tokens` задаёт включительный предел ввода для этой цены;
выше него оценка unknown. Условия тарификации, которые формат не выражает,
нельзя превращать в полную стоимость запроса. Цена API не описывает подписку.
Ревизия сохранённой цены может быть старше ревизии самого снимка.

## Отбор и происхождение

Профиль требует текстовый ввод, потоковый текстовый ответ и вызов функций.
OpenRouter фильтруется по modalities, supported parameters, tokenizer и сроку
доступности. Batch-варианты, динамические маршрутизаторы и несовместимые
записи исключаются. Возможности не выводятся из имени модели.

Нативные записи проверяются по отдельности. Их provenance фиксирует
основания metadata, исключения и ограничения; OpenRouter provenance связывает
нормализованный JSON с публичным снимком. Генерация отклоняет несовпадающие
hashes, ревизии, профили и ID нативных записей.

Формат не описывает все сочетания параметров, одновременные effort и manual
budget, hosted tools, аудиовывод или entitlement аккаунта. Потребитель
проверяет запросы с учётом своего сериализатора и выбранного API.
